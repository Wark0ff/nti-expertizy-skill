# Экспертизы проектов TechNet (НТИ)

Файлы скила:
- `scripts/nti_parser.py` – парсер площадки: свободные проекты, отсев занятых и уже оценённых, презентации.
- `scripts/mk_exp.py` – оформление docx/html из JSON и автопроверка критериев на дословность.
- `references/criteria.md` – шкалы критериев (копировать слово в слово) и образец готовой экспертизы. Прочитать перед написанием.

Требования: Python 3, `pip install requests python-docx openpyxl`. Скрипты запускать по полному пути из папки скила, результаты писать в рабочую папку пользователя.

## 0. Спросить в начале

1. Сколько экспертиз (по умолчанию 3) и имя исполнителя для колонки «Кто взял».
2. Таблицу распределения команды: ссылка на Google Таблицу (если есть доступ), файл .xlsx/.csv или вставка текстом. Колонки: №, ИД/ссылка, Название, Рынки, Кто взял, Статус, Комментарий. Без неё не начинать.
3. Нужны ли Google Доки или достаточно .docx.

## 1. Занятые проекты

- Занят любой проект, ID которого (`ideas/NNNNN`) есть в таблице команды, при любом статусе: «Первичный отбор», «Берем на экспертизу», «В работе», «Экспертиза написана», «Экспертиза опубликована» – взят; «Не берем на экспертизу», «ПРИЧЕМ ТУТ ТЕХНЕТ?» – отсеян.
- Прочитать «Комментарий»: причины отсева (нет презентации, это AeroNet, уровень идеи, один исполнитель). Похожие не брать.

## 2. Поиск кандидатов

1. Сохранить таблицу команды как `plan.csv` (или `.xlsx`) и запустить:
   `python <скил>/scripts/nti_parser.py --plan plan.csv --pages 60 --top 80` (5–10 минут, лучше в фоне).
2. Парсер:
   - собирает ленту TechNet «Не взято в экспертизу» и ленту «На экспертизе»;
   - отсеивает начатые и готовые экспертизы на площадке: проект в «На экспертизе» или счётчик на карточке «Экспертные заключения» больше 0;
   - отсеивает проекты из таблицы команды;
   - склеивает дубли карточек (занята одна – заняты все);
   - оценивает профиль TechNet по словам (станки, производство, материалы, аддитивка, датчики, диагностика, автоматизация, робототехника, машиностроение; штраф за образование, агро, медицину, туризм, финансы, торговлю, БПЛА/AeroNet, чат-боты);
   - находит на pt.2035 презентацию и стадию.
   Итог: `candidates.csv` (сначала с презентацией) и `all_projects.json`.
3. Брать только проекты с презентацией (`pres`). Новые проекты часто без неё, поэтому страниц 40+.
4. Просмотреть описания глазами: оценка по словам грубая.
5. Если сайт не отдаёт страницы без входа – попросить пользователя открыть ленту во встроенном браузере под своим аккаунтом.
6. Показать пользователю 5–7 кандидатов (ID, название, стадия, почему подходит), дождаться выбора и сразу дать строки для таблицы со статусом «В работе».

## 3. Изучение проекта

- Скачать и прочитать презентацию целиком и страницу проекта: проблема, решение, стадия, что сделано (макет, стенд, испытания, пилоты), команда, рынок, конкуренты, монетизация, ИС.
- Факты только из материалов проекта, ничего не придумывать.
- Контакты (телефоны, email) не переносить.

## 4. Текст экспертизы

1. Заголовок: полное название проекта.
2. Абзац 1 – суть и актуальность: «Проект предлагает решение проблемы…», технология, для кого актуальна.
3. Абзац 2 – что сделано: потребители, макет/стенд, испытания, научное руководство, партнёры, планы пилота. Только подтверждённое.
4. Абзац 3 – рекомендации: «Рекомендуется…» – конкурентный анализ (отечественные и зарубежные аналоги), оценка рынка, бизнес-модель и ценностное предложение по сегментам, подтверждение характеристик, защита ИС, усиление команды, доработка презентации (назвать пустые разделы).
5. 7 критериев – значения из `references/criteria.md` слово в слово. Для TechNet направление почти всегда «Другое».
6. Строка `Проект: https://experts.nti.work/improject-47/ideas/NNNNN`.

Стиль: деловой, 3–6 предложений в абзаце, только короткое тире «–», без ИИ-штампов и восторгов. Ориентир – образец в `references/criteria.md`.

Уровни без завышения: макет или стенд → TRL-3, лабораторный образец с испытаниями → TRL-4; рынок назван без конкурентов и бизнес-модели → MRL-1; неполная команда, но есть вуз или ментор → CRL-3; нет оценки объёма рынка → IRL-0.

## 5. Оформление

Записать экспертизы в `expertizy.json` (формат в шапке `mk_exp.py`) и запустить:
`python <скил>/scripts/mk_exp.py expertizy.json --who <Имя> --out <папка>`
Скрипт сам проверит дословность критериев, длинные тире, контакты и ID; при ошибке файлы не создаются. На выходе `Экспертиза_<имя>.docx` и `.html` на каждый проект и общий `ГГГГ_ММДД_Экспертизы_<Имя>.docx`. HTML – для вставки в форму площадки или Google Док без потери жирного.

Google Доки – только если просили; доступ не открывать без согласия.

Строки для таблицы команды (отдать текстом, вносить самому только с согласия):
`№ | https://experts.nti.work/improject-47/ideas/NNNNN | Название | Рынки | <Имя> | Экспертиза написана | короткий комментарий`

## 6. Проверка перед сдачей

1. Проект не взял никто другой: ещё раз таблица команды и карточка на площадке («Экспертные заключения: 0», не в «На экспертизе»). Быстро: `nti_parser.py --plan plan.csv --pages 60 --top 0` и найти ID в `all_projects.json`.
2. Каждый факт абзацев 1–2 есть в презентации или на странице проекта.
3. Уровни не противоречат тексту и друг другу.
4. Открыть docx: жирные заголовки и переносы на месте.

## Что отдать

Коротко: какие проекты взяты (ID и название), файлы, строки для таблицы. Без отчёта о проверке.
